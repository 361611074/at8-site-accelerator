## 划分原则

下面这些设想也要守住同一条底线：

Free 版必须**独立可用**，不是"功能阉割的试用版"。
一个只用 Free 版的站长应该能获得完整、可解释的加速效果；
Pro 卖的是**规模化运维能力**（多站点、CDN、自动化），不是"把 Free 拆一半藏起来"。

三条硬规则：

1. Free 版不设时间限制、不设用量限制、不弹升级广告；
2. Free 版不故意留下"半成品功能"（例如只做一半的懒加载）；
3. Pro 版不通过关闭 Free 已有功能来制造差异。

## 为什么这些划到 Pro

| 功能 | 划到 Pro 的理由 |
| --- | --- |
| 缓存预热 | 会主动发起大量请求。做不好就是"缓存插件把源站打挂"。必须配队列、限速、失败重试，工程量大且必须可观测。 |
| Critical CSS | 需要无头浏览器渲染每个模板，是独立的基础设施。 |
| JS 延迟执行 | 需要处理依赖顺序（`defer` 顺序敏感），兼容性风险高，必须配逐脚本排除规则。 |
| 多服务器同步 | 需要共享存储或失效总线，是运维架构问题而非插件功能问题。 |
| 分角色缓存 | 缓存键空间会随角色数线性膨胀，且极易因漏判角色导致内容串号（安全问题）。 |
| AVIF | 编码耗时是 WebP 的数倍，必须队列化，否则会拖慢上传。 |
| 白标 | 纯商业需求。 |
| 趋势图表 | 需要长期存储时间序列数据，Free 版不应该引入额外数据表。 |

## Pro 版本形态（尚未实现，仅记录方向）

- 独立插件，复用 Free 版的 `includes/` 基础层；
- Free 已装时自动检测并接管，避免两份缓存；
- 授权：站点级 license key，支持本地开发环境免授权；
- 更新：自建更新服务器（`update_plugins` 钩子）。
